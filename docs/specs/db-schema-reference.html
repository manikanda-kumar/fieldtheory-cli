Overview

The primary database (bookmarks.db) holds three layers: X/Twitter bookmark rows, a unified canonical layer that deduplicates across sources, and link enrichment cache for daily digest generation. A separate following.db indexes the X following roster.

Data flow

JSONL caches bookmarks.jsonl, raindrop, github-stars, projects → indexed into SQLite
bookmarks table Per-tweet X bookmark records with classification and article enrichment
canonical layer bookmark_sources → canonical_bookmarks (dedupe by url or tweet id)
Search FTS5 virtual tables with BM25 ranking; external-content FTS (no triggers)

Dedupe key rules

  • URL sources: url:{normalized-url} — lowercase host, strip tracking params, no fragment
  • Ambiguous X bookmarks: x:{tweetId} when no single clear external link
  • Canonical id: canonical:{sha256(dedupe_key)}

Migrations & operational notes

bookmarks schema migrations

ensureMigrations() in bookmarks-db.ts is column-driven, not version-gated. It adds missing columns and rebuilds FTS when article_text is absent from the FTS table.

  • Added: domains, primary_domain + index
  • Added: quoted_tweet_json
  • Added: article_title, article_text, article_site, enriched_at
  • Added: folder_ids, folder_names
  • FTS rebuild drops and recreates bookmarks_fts when schema drifts

canonical schema migrations

  • bookmark_sources: content_path, metadata_json added via ALTER TABLE
  • canonical_bookmarks: categories, primary_category, domains, primary_domain

Concurrency

  • Lock file: {dbPath}.lock with 10-minute stale detection
  • Canonical rebuild and enrichment writes use acquireDbLock()
  • Save pattern: write temp → fsync → rename → fsync parent directory

JSON column conventions

  • Arrays stored as JSON strings: links_json, tags_json, github_urls, folder_*
  • Some fields use comma-separated strings instead: categories, domains
  • Booleans stored as INTEGER 0/1: verified, active
